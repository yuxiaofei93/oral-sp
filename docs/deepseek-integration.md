# DeepSeek 接入说明

## 使用范围

MVP 使用同一个 `deepseek-v4-flash` 模型完成两类工作：

- 患者语义路由：关闭思考，根据当前问题、最近对话和允许披露的患者事实返回相关事实编码。
- 患者回答：关闭思考，只能使用语义路由选中的患者事实作答，并把病历式事实改写成患者现场会说的自然口语。
- AI 辅助评价：启用低强度思考，输出逐项分数、置信度、证据引用、理由和改进建议。

教师需要在单份已结束答卷中显式触发 AI 评价。反馈发布后不能新建或重跑 AI 评价；仍有 AI 调用进行时也不能发布反馈。教师逐项复核始终拥有最高优先级。

## 服务端配置

复制示例环境文件后，只在本机或服务器的 `.env` 中填写密钥：

```dotenv
LLM_PROVIDER=deepseek
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=sk-替换为真实密钥
LLM_MODEL=deepseek-v4-flash
LLM_TIMEOUT_SECONDS=30
```

`.env` 已被 Git 忽略。真实密钥不得出现在前端变量、病例内容、日志、截图、提交记录或聊天消息中。更换配置后重启 API 服务。

## 输入与持久化边界

患者语义路由发送当前问题、最近 12 条对话和所有允许披露的患者事实，但不发送标准诊断、标准检查解释、评分答案或用户身份。患者回答只发送当前问题、最近对话和路由选中的事实。AI 辅助评价只发送：

- 病例版本 ID 和待评价评分项；
- 问诊消息与阶段提交；
- 标准诊断及标准检查；
- 消息或提交的随机 ID，供证据引用。

系统不发送学生姓名、邮箱、班级或教师身份。模型返回的证据引用必须对应本次输入中的消息或提交；证据摘录由服务器从原始记录重新生成，模型不能自行写入证据文本。

系统持久化最终结果和调用元数据，不持久化思维链。每次成功或失败的 AI 评价都是独立运行记录，不覆盖历史版本；半年数据清理会随会话一并清理这些记录。

## 失败与重试

- 空内容或无效 JSON：同一请求最多受控重试一次。
- 患者回答照抄病历式事实：追加明确的口语化纠正后重试一次；仍照抄时不返回模型原文，改用受控规则回答并记录 `response_not_conversational`。
- 输出截断：标记失败，不采用不完整分数。
- 越界分数、缺失评分项、未知评分编码或虚构证据：整次评价失败，不部分写入。
- 网络、限流或 DeepSeek 服务错误：返回明确错误码，教师可稍后重试。
- 同一答卷、输入、供应商和模型未变化时，普通点击复用已有成功结果；“重新生成”才创建新版本。

真实接口冒烟测试应使用不含真实学生个人信息的演示病例，并检查教师答卷页显示的实际模型版本、耗时、token 数、证据和分数范围。
