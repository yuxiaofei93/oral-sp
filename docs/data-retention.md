# 数据保留与清理说明（MVP）

## 保留期口径

问诊会话及其消息、病例草稿与最终记录、模型调用、评分证据和教师复核从会话实际结束时保留 180 天。

- 正常交卷：从最终病例记录提交成功的时间开始计算。
- 学生计时超时：从服务端确认超时的时间开始计算。
- 教师结束任务：从结束任务使会话结束的时间开始计算。
- 任务截止后一直没有再次访问的旧会话：清理命令执行时先把超时状态落库，并从该时间重新保留 180 天，本次不会立即删除。

即使保留期已经结束，只要任务最晚截止时间尚未到达，清理命令也不会删除该会话，避免旧任务仍可进入时移除“一次作答”记录。

## 命令安全规则

默认命令是 dry-run，只输出：

- 待落库的超时会话数量。
- 符合删除条件的会话数量。
- 对应消息、病例记录、模型调用、评分项和教师复核数量。

```bash
.venv/bin/python apps/api/manage.py purge_expired_simulation_data
```

只有显式添加 `--execute` 才会先处理超时状态并删除符合条件的数据：

```bash
.venv/bin/python apps/api/manage.py purge_expired_simulation_data --execute
```

删除不可从应用内恢复。生产环境执行前必须确认 dry-run 输出并完成可恢复的数据库备份。

## 运行建议

MVP 可每月低峰期运行一次。先在日志中保存 dry-run 结果，再执行正式命令；部署方应把命令纳入备份、监控和恢复演练流程。低配主机无需为此常驻 Redis 或任务队列。
